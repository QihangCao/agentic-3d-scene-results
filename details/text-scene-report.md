# 三场景 3D 生成基准 — 结果与多轮迭代汇报

整理日期 2026-09-14 · 数据截至 2026-09-10 · 公开展示版

---

## 一句话结论

三个类型完全不同的场景，用同一套「构建 → 全判据集渲染 → 五路独立盲评 → 定位修正」循环迭代，**全部收敛到 84–87 分区间，全部未达到 90 分退出门槛**。前 5–6 轮拿到绝大部分增益，之后每轮约 +0.3 分，成本却不降。

### 两次下跌，成因完全不同

- **后厨第 2 轮 58.0（−2.1）** —— 真实缺陷。一个过期的变换把三滴酱汁放大到 **2 米**，挡住多个机位。原因定位为依赖更新，已修复；出问题的图**保留未删**。
- **街景第 7 轮 84.2（−1.3）** —— 不是回归。换了一组新评审员，材质/痕迹/构图三项独立打低。**分数不强制单调**，这是刻意的设计：如果允许后一轮继承前一轮分数，评审就失去独立性。

## 4. 成本

| | 街景 | 后厨 | 住宅 v3 |
|---|---:|---:|---:|
| agent 数 | 69 | 48 | 未计量 |
| 输入 token | 249.1 M | 125.4 M | 未计量 |
| 缓存命中率 | **96.4%** | **97.1%** | 未计量 |
| 输出 token | 892 K | 579 K | 未计量 |
| 其中推理 token | 237 K | 216 K | 未计量 |
| LLM 成本 | $112.24 | $56.21 | 未计量 |
| GPU 成本 | $95.07 | $89.91 | $63.73 |
| **合计** | **$207.31** | **$146.11** | ≥ $63.73 |

计价假设：输入 $3/M、缓存输入 $0.3/M、输出 $15/M、GPU $3/GPU-h（见 `data/*_cost_record.json`）。

两点值得注意：

1. **缓存命中率 96–97%** —— 若无缓存，街景的输入成本会从 $99 涨到约 $747。长上下文多轮迭代场景里缓存不是优化项，是可行性前提。
2. **GPU 与 LLM 成本量级相当**（街景 46% : 54%，后厨 62% : 38%）。渲染不是零头。

## 6. 方法论

每一轮包含：

1. **构建 / 修改** —— 按上一轮诊断执行具体修正
2. **全判据集渲染** —— 相机位姿冻结，保证跨轮可比
3. **五路独立评审** —— 城市/功能、材质·光照·磨损、构图、几何·技术、占用感。评审员打开实际全分辨率 PNG，在综合前**互相盲评**
4. **综合打分与诊断** —— 定位下一轮要改什么
5. **存档** —— `checkpoints/cycleXX_reviewed.blend` 保留该轮被评审的场景状态

关键约束：

- **相机冻结**。街景 14 台相机自第 2 轮起不变，跨 9 轮可比；后续补充相机只增不换。
- **不回填分数**。早期的技术分带 `*` 标记为「临时」，拿到冷启动/导出证据后**不追溯修改历史分**。
- **技术通过不抵艺术门槛**。街景技术分 4.5/5、GLB 独立校验全过，但这不会让使用痕迹从 12.5 变成 13。

## 7. 诚实的局限

- **三个场景都没过 90 分门槛。** 本包记录的是真实基准结果，不是验收通过声明。
- **住宅 v3 不可比。** 它只跑了 3 轮就因作业配额到期被 CANCELLED（`13288542`，跑满 2:39:20），没有最终维度评分、没有最终 GLB 导出、没有冷启动比对。把 83.7 和另外两个并列看会低估它——也可能高估，因为它从未接受最终门禁检查。
- **GLB 不等于原生外观。** 世界环境、体积、区域光和程序化遮罩在 glTF 里是近似的。`.blend` 和 Cycles 渲染图才是权威。
- **冷启动是随机性接近，不是逐字节一致。** 街景 RGB 平均绝对差 0.034/255 和 0.044/255，后厨 0.033/255，均远低于 0.5/255 容差。
- **运行时审计是采样检查**，不是完备的碰撞或规范合规证明。
- **街景 tour 落后最终场景一轮**（见第 5 节）。

## 8. 值得进一步研究的问题

**三个类型迥异的场景，全部收敛在 84–87，全部卡在 90 以下。** 这个天花板更可能来自评审机制本身，而不是场景难度 —— 同一模型的不同上下文实例，对「什么算 90 分」可能有一致的误判。三个独立场景落在 3 分的窄带内，这个巧合值得验证。

两个可检验的方向：

1. **换评审模型/换 rubric 表述重跑最终场景的评分**，看 86.9 是否稳定。如果分数显著移动，天花板在评审侧。
2. **止损点**。街景第 7–10 轮花了约 40% 预算换 1.4 分，第 10 轮只换来 0.1 分。如果引入「连续两轮增益 < 0.5 即停」的规则，街景在第 8 轮左右就该停，省下约 $60，代价是 2 分。

另一个观察：两个场景卡住的维度（街景「使用痕迹」、后厨「占用感」）本质是同一件事 —— **可信的不规则性**。这是当前流程最弱的一环，且连续多轮定向修正都推不动。
